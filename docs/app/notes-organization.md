# Notes organization implementation

Decision (2026-10-17): combine the three approved design studies into one Notes page. Folders provide one familiar home; tags cross folder boundaries; the Scripture atlas is a filter, not a second store of notes. All notes remains the default entry, and older notes are initially visible in Inbox without rewriting them. See [the active note contract](../../specs/app/notes-v1.md#foldertag-organization-2026-10-17) for commands, storage, migration and limits.

Verification: engine integration tests cover reopening, tag normalization/deduplication, atomic rollback, note preservation when deleting a folder and cascade cleanup when deleting the note. Frontend tests cover intersection filters, legacy Inbox behavior, tag search and canonical sorting. Browser review exercises folder creation and applying folder/tags together. Android installation and physical screenshots are recorded separately in the delivery conversation; automated checks alone do not establish physical-device UX or large-library performance.

Picker theme correction: all six authored native `<select>` controls in the TypeScript app now use the shared `ThemedPicker` (HeroUI Select/ListBox): note sort, Scripture book filter, destination folder and passage-attachment book/chapter/verse. Open menus render inside the themed overlay root, including when nested in a sheet, with selected-state checkmarks, scroll bounds and keyboard navigation. Android's OS select dialog no longer determines their menu colors. This presentation-only correction does not change notes, resources or engine commands.

Notes visual simplification (2026-10-17): phone review showed the folder, filter, sort and selection controls competing with the notes. The list now has one integrated search field and one compact folder/filter/view-options row. Sorting and bulk-selection entry live under View options, with a quiet current-sort caption. Cards have one action menu, plain tag links and reduced metadata emphasis. The decorative eyebrow, subtitle and duplicate total are removed from this page. All existing organization/search capabilities remain reachable; no storage or command changes.

Organization success feedback now uses a compact floating status message instead of a persistent list row. It auto-dismisses after 3.5 seconds, restarts its timer for repeated identical actions, supports immediate dismissal and clears its timer on unmount. Errors remain available until addressed; no data or protocol changes.
