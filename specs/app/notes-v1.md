# App note documents v1

Local implementation, 2026-10-17. Approved visual/interaction references are `design/notes-studies/`, `design/selection-notes/` and `design/scrapbook-notes/`. Static prototypes do not define production content.

## Compatibility and storage

Published `data/schema/user-v1.sql`, SQLite user_version=1, canonical IDs and annotation IDs remain unchanged. The engine creates app-owned `fontes_notes_v1(annotation_id TEXT PRIMARY KEY REFERENCES annotations(id) ON DELETE CASCADE, document_json TEXT NOT NULL) STRICT` after user-store validation. Notes remain `annotations.type='note'`. Plain `annotations.content` is a readable flattened fallback, preserving source citations for older readers. Legacy plain notes open without migration; editing through the new editor creates a document. Legacy `annotation.save` removes a note extension in the same transaction, preventing stale rich content after an older editor changes plain text. Deletion cascades only the chosen annotation extension.

## Commands and validation

The generated `commands-v1.json` is authoritative. `note.save` accepts optional existing note ID, canonical inclusive start/end, and a document: title, pinned, blocks and optional exact edition-bound selection. It atomically stores annotation fallback, provenance and document. Existing highlight IDs cannot be converted via this command. Titles are bounded to 512 bytes; 1–200 blocks; input documents at most 100,000 UTF-8 bytes, normalized documents at most 150,000 bytes, flattened text at most 100,000 bytes. Thoughts must be nonblank (the UI omits unfinished empty thought blocks when saving).

Blocks are tagged `thought` (text), `passage` (canonical ref_id, translation_id, exact quote), and `resource` (resource_id, exact quote, engine-derived title/author/source/content_id). Dictionary definitions use the same source-resource block, preserving their actual dictionary title/code rather than inventing linguistic content. Source metadata supplied by clients is replaced by installed metadata. Passage and resource quotes must be exact nonempty substrings of the supplied edition/resource; resource comparison uses the same numeric-entity compatibility normalization as resource display. Paragraph selection can be refined to an exact excerpt before insertion. Source HTML is never executed.

A note selection uses the rich-highlight `TextSelection` contract: ordered verse IDs, Unicode scalar half-open offsets and exact quotes. Validation is shared with highlights. Stored identical selection and source blocks may survive missing/changed library content when editing unrelated note text. A retained selection exception applies only at its unchanged canonical range. New/changed clips/anchors require installed-source verification. The notebook and saved excerpts remain readable when source data is absent. Markers are rendered only when selected text still matches the anchored edition and exact offsets; no automatic remapping.

`note.passage { ref_id }` returns tagged `note_passage { block }`, the exact current-edition verse, without changing reading selection/session. It supports passage collection while the note remains open. The command registry grows additively from 15 to 17; no protocol/SQL/content-download change. Workspace adds default-empty `notes: [{ annotation_id, document }]` alongside legacy annotations/highlights.

## UI behavior

Notes opens a searchable notebook with Notes/Highlights/Bookmarks filters and recent/oldest ordering; pinned notes precede others. Cards expose passage context, thought previews, selected quotes and collected-piece counts. Secondary navigation/edit/delete actions live under More. Deletion retains explicit confirmation. The calligraphic plus is fixed above navigation, hidden when no note exists; first-note CTA is the only creation action in that empty state.

Holding Scripture enters adjustable selection without word-study navigation. Context actions are Add note, Highlight and Done selecting. Add note transfers the exact anchor to the editor. Notes sharing a selected endpoint group in a counted marker beside that wrapped text line; the gutter reserves space so markers do not obscure Scripture. Legacy range notes have a verse-end marker. Marker opens a modal with every attached note and Add another note; notebook cards also open this modal. Different selections sharing an endpoint may be grouped; each retains/displays its own quote.

Editor supports title, pinning, thoughts interleaved with sourced blocks, insertion after a piece, up/down reordering, removal with one-step Undo, explicit Save, and confirmation before discarding a draft. The initial thought remains a separate opening editor; additional thought blocks can be interleaved/reordered. Add to note searches installed passages/resources, previews exact passage text or selectable source paragraphs, and inserts the chosen piece. Study resource articles expose Add excerpt to note; cross-reference cards expose Add passage to note. Collection targets a new or existing note. Source context modals retain excerpts and can load the current source without throwing away the draft.

No unrestricted HTML embeds, media uploads, sync, rich inline formatting, arbitrary external websites or export are implemented. The current source picker previews the first 201 nonblank paragraphs with exact-excerpt editing/pasting available beyond that. Reading profile naturally lacks study resources but supports thoughts and passage clippings. Full physical-device accessibility audit, keyboard-height ergonomics and missing-source notification refinement remain separate verification work.
